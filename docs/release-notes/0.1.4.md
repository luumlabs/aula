# Aula 0.1.4

**Release candidate: not published. Apple signing, notarization and a notification check on the signed app are still required.**

## What's new
- Mac distribution now requires a Developer ID Application signature, hardened runtime and Apple notarization.
  A release cannot silently fall back to the old local signature or an unsigned build.
- Test a notification from Settings to check delivery. Aula reports when the system cannot confirm delivery and
  explains where to check notification permissions and Focus settings.
- Short app notifications stay alive while the system handles them; delivery failures are recorded in Aula's log.

## Install
Planned artifacts (publish only after validation): `Aula-0.1.4-mac.dmg`, `Aula-Setup-0.1.4.exe`,
`Aula-0.1.4-linux-x86_64.AppImage`, `Aula-0.1.4-linux-arm64.AppImage`, `Aula-0.1.4-linux-amd64.deb`.
The Linux `.deb` is installed manually; it does not update itself.

This release changes the signing identity. Copies signed with **Aula Local Signing** (including 0.1.3) cannot install
it automatically: download the Mac DMG from this release, quit Aula and replace the app in Applications once.
Do not remove Aula's data folder. macOS may ask for permission to access the existing Aula Safe Storage keychain item
again because the signing identity changed. Future updates continue to verify the developer's identity and Aula's
own update signature.

After opening Aula, use the notification test and allow notifications in System Settings if needed. Signing does
not override notification preferences or Focus. Background reminders require Aula to be running.

This is the desktop release. It does not include the mobile work in progress or an App Store submission.

licensed under the [GNU AGPL v3](https://github.com/luumlabs/aula/blob/v0.1.4/LICENSE.md).

# Aula 0.1.4

**Versión candidata: aún no publicada. Faltan la firma de Apple, la notarización y probar una notificación en la app firmada.**

## Lo nuevo
- La distribución para Mac exige firma Developer ID Application, hardened runtime y notarización de Apple.
  Una compilación de distribución ya no puede recurrir silenciosamente a la firma local antigua ni quedar sin firma.
- Puedes probar una notificación desde Ajustes. Aula indica si el sistema no confirma la entrega y explica dónde
  revisar los permisos de notificaciones y los modos de concentración.
- Los avisos breves de la app se conservan mientras los procesa el sistema; los fallos quedan registrados en el log.

## Instalar
Archivos previstos (publicar solo tras verificarlos): `Aula-0.1.4-mac.dmg`, `Aula-Setup-0.1.4.exe`,
`Aula-0.1.4-linux-x86_64.AppImage`, `Aula-0.1.4-linux-arm64.AppImage`, `Aula-0.1.4-linux-amd64.deb`.
El paquete `.deb` de Linux se instala a mano; no se actualiza solo.

Esta versión cambia la identidad de firma. Las copias firmadas con **Aula Local Signing** (incluida la 0.1.3) no pueden
instalarla automáticamente: descarga el DMG de esta versión, cierra Aula y reemplaza la app en Aplicaciones una vez.
No borres la carpeta de datos de Aula. Como cambia la identidad, macOS puede volver a pedir permiso para acceder al
elemento Aula Safe Storage del llavero. Las actualizaciones posteriores siguen verificando la identidad del
desarrollador y la firma propia de las actualizaciones de Aula.

Al abrir Aula, prueba una notificación y permite las notificaciones en Ajustes del Sistema si hace falta. La firma no
anula tus preferencias ni los modos de concentración. Los recordatorios en segundo plano necesitan Aula en ejecución.

Esta versión es de escritorio. No incluye los cambios móviles en desarrollo ni un envío a la App Store.

**Código fuente:** los archivos *Source code* de esta versión (etiqueta `v0.1.4`) deben corresponder exactamente a los
instaladores distribuidos, con la licencia [GNU AGPL v3](https://github.com/luumlabs/aula/blob/v0.1.4/LICENSE.md).
